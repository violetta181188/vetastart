# VetaStart — платформа автоматизации Instagram

> **Статус:** тестовый личный кабинет. Реальная отправка сообщений Instagram, проверка подписки и приём платежей пока не включены.

## Тестовое приложение

- Интерфейс: https://vetastart-cabinet-test.onrender.com/
- Ветка разработки: `staging/cabinet-v1`
- Production-ветка: `main` — **не изменять без проверки**
- Стек: Node.js 22, Express 4, PostgreSQL 16
- Авторизация: scrypt-хеширование паролей и серверные сессии с HttpOnly-cookie.

## Сейчас реализовано

- Регистрация и вход по email/паролю; пароль не менее 12 символов.
- Профиль: изменение имени и пароля (после смены пароля остальные сеансы закрываются).
- Выгрузка своих проектов/сценариев: `GET /api/account/export`.
- Проекты Instagram без реального подключения к Meta (черновики).
- Один серверный источник данных для конструктора и кабинета — PostgreSQL.
- Создание, редактирование, удаление сценариев, активация и уникальность ключевых слов в рамках одного проекта.
- До **10 активных сценариев на проект**, до **5 сообщений** и 3 кнопок выбора в сценарии.
- Тёмная тема по умолчанию; светлая — переключатель.
- Тарифный *расчёт* (не списание): **990 ₽/мес до 3 аккаунтов; +299 ₽/мес за каждый следующий**.
- Проверка подписи входящего webhook Meta; **обработка событий и отправка сообщений ещё не реализованы**.

## Что НЕ готово

1. Meta OAuth и выдача разрешений Instagram для клиентских аккаунтов.
2. Обработка комментариев/Direct, правила переписки, отправка кнопок и файлов.
3. Реальная проверка подписки Instagram (если поддерживается выбранным API/разрешениями).
4. Сбор аналитики реальных событий, привязка переходов и покупок.
5. Робокасса: одобрение магазина, безопасный callback, рекуррентные платежи и контроль доступа.
6. Подтверждение email, восстановление доступа и админ-панель.
7. Тесты браузерных пользовательских сценариев, защита от злоупотреблений, мониторинг.
8. Постоянная база данных и резервное копирование до запуска для платящих клиентов.

**Не предлагать покупку или подключение Instagram как работающую функцию до завершения этих этапов.**

## Данные и безопасность

- В базе `users`, `sessions`, `instagram_accounts`, `scenarios`.
- Все пользовательские API требуют сессию, сценарии изолированы по владельцу.
- Ключи и пароли не записывать в GitHub.
- Клиентские секреты передаются через Environment Variables в Render.
- Тестовая БД Render — **free**, истекает **16 декабря 2026**. Нельзя использовать её для постоянного хранения клиентских данных без миграции на устойчивый тариф или иного провайдера с бэкапами.

## Разработка

```bash
npm install
npm run check
npm test
npm start
```

Для реальной базы нужен `DATABASE_URL`. Миграция `migrate.js` запускается через `bootstrap.js` перед сервером. Ключи никогда не публикуются.

Статус сервера: `GET /healthz`. Endpoint `/dashboard.js` отдаёт frontend-контроллер.
