## Подтверждённые результаты

- Meta OAuth завершён владельцем; сохранено активное Unified Login подключение.
- Токен действителен, app ID совпадает, instagram_manage_messages предоставлено.
- App-level webhook активен, callback совпадает с основным сервисом, поле messages есть.
- Подписка аккаунта возвращает запись subscribed_fields=[messages] без app ID.
  Отсутствие app ID в таком ответе нельзя интерпретировать как пустую подписку.
- Два тестовых запроса из панели Meta прошли проверку подписи и сохранены.
- Настоящее сообщение от тестировщика не поступило. Причина на стороне доставки
  или прав Meta пока не доказана. Непубликация приложения видна в панели, но сама
  по себе не является достаточным доказательством причины для тестовых аккаунтов.

## Проверить в панели владельца Meta

1. В сценарии Instagram открыть шаг «Пройдите проверку приложения» и получить
   текущий список требований и статусы доступа разрешений. Не объявлять публикацию
   единственной причиной проблемы без этих данных.
2. Сопоставить текущее приложение с Instagram tester invitation: имя ранее
   авторизованного VetaStart-IG само по себе не доказывает принятие роли для
   текущего Meta app ID. Оба аккаунта перечислены как Instagram testers.
3. Для Direct нужны только реально используемые разрешения. Текущий токен также
   содержит ads_management, ads_read, instagram_manage_comments,
   instagram_content_publish. Не заявлять для проверки неподдерживаемые функции:
   реклама, публикация контента и ответы на комментарии не являются готовыми
   возможностями этой версии.
4. Подготовить демонстрацию реального сценария: вход, выбор аккаунта, ключевое слово,
   входящее сообщение, ответ в пределах 24 часов, отключение сценария и отзыв доступа.
   Не подменять эту демонстрацию синтетическим webhook-тестом.
5. Выполнить запрошенные Meta проверки владельца/компании и предоставить сведения
   о юридическом владельце. Не выдумывать регистрационные данные бизнеса.

## Что пока блокирует полноценный коммерческий запуск

Проверка через официальный conversations API обнаружила два недавних сообщения
«VETASTART ТЕСТ» от ожидаемого аккаунта отправителя. Значит, чтение Direct этим
токеном доступно; Business Verification нельзя объявлять причиной недоставки
уведомлений. Синтетические webhook-тесты доставляются, реальные webhook пока нет.

Реальные webhook Direct не подтверждены; контролируемое чтение и одна отправка
через API подтверждены ниже. Открытая регистрация и SMTP
не включены; магазин Робокассы активирован 23 ноября по сообщению владельца,
но интеграция и тестовый платёж ещё не подтверждены. Для базы нужен постоянный план
с резервированием. SUAT management refresh, фискализация, возвраты и регулярные
списания не завершены. Business Verification отправлена пользователем;
App Review не отправлена и приложение не опубликовано.

Для изолированной диагностики `/api/admin/instagram/accounts/:id/test-inbox`
читает до 10 переписок и до 5 последних сообщений каждой переписки, ищет только
известную тестовую фразу за последние 24 часа и возвращает агрегированные счётчики.
Доступ ограничен ключом владельца и аккаунтами без клиентского владения. Тексты и
идентификаторы переписок не возвращаются, не сохраняются и не попадают в очередь;
при отказе Meta сохраняются только HTTP-статус и числовые коды ошибки.

Для одного контролируемого ответа PostgreSQL предоставляет защищённые маршруты
`POST /api/admin/instagram/accounts/:id/test-reply/prepare` и
`POST /api/admin/instagram/accounts/:id/test-reply/:draftId/send`.
Подготовка выбирает последнее недавнее тестовое сообщение только от известного
отправителя, сохраняет один черновик и не отправляет его. Отправка требует
администраторского ключа и JSON confirm=send-one-test-reply, использует sender с
фильтром ровно одного draftId, проверкой включённого сценария и окна 24 часа.
Повторная попытка не пересылает уже обработанный черновик. Эта операция не меняет
общие флаги отправки или фоновой автоматизации и не принимает аккаунты клиентов.
Первая реальная отправка требует явного согласия владельца на получателя и текст.

Первый контролируемый ответ отправлен после явного согласия владельца.
Meta подтвердила одну отправку; владелец подтвердил получение в тестовом аккаунте.
Это доказывает чтение и отправку через API, а не доставку реальных webhook.

Добавлен резервный опрос официального conversations API для одного аккаунта
владельца, с durable lease и дедупликацией событий API/webhook. Начальный приём
начинается с момента активации; исторические сообщения не импортируются.
Режим подготовки черновиков может работать с VETASTART_SEND_ENABLED=false.
Для круглосуточного исполнения остаётся вопрос не засыпающего хостинга;
существующий бесплатный Render этого не гарантирует.
