# Worker на существующем сервере Timeweb

Пакет подготовлен для VPS `vetastart-site-bot`, на котором уже расположен
сайт vetastart.ru. **Установка на реальном VPS ещё не выполнена.** Нет доступа
к консоли сервера; прямое SSH-соединение из текущей среды не проверено успешно,
а GitHub-интеграция не предоставляет права Actions. Не сбрасывать сервер,
операционную систему, пароль, DNS или настройки сайта ради установки worker.

Установщик создаёт отдельные `/opt/vetastart-worker`, `/etc/vetastart-worker`,
системного пользователя и systemd service. Порты не открываются, nginx и существующая
версия Node сайта не изменяются. Node 24.22.3 устанавливается в частный каталог,
архив проверяется по SHA256 официального дистрибутива; исходники берутся по
обязательному проверенному commit SHA, npm lifecycle-скрипты отключены.

## Перед запуском

- Войти в штатную консоль существующего VPS через свой Timeweb аккаунт.
- Проверить, что используется Debian/Ubuntu с systemd и что ресурсы сервера
  позволяют запустить отдельный Node процесс (лимит worker: 384 MB и 25% CPU).
  Установщик требует минимум 384 MB доступной памяти и 768 MB свободного диска;
  при нехватке ресурсов он останавливается, не меняя тариф сервера.
- Иметь доступ к Render API key. Ввести его только в скрытом запросе установщика
  в доверенной консоли VPS; не присылать в чат. Установщик не сохраняет этот ключ.
- Свободный доступ сервера к HTTPS GitHub, Node, npm, Meta и к внешнему PostgreSQL
  Render обязателен. Проверка внешнего подключения выполняется со строгим TLS.
- Сначала посмотреть план: `bash install-worker.sh --ref COMMIT_SHA --dry-run`.
  Затем выполнить этот же файл от root без `--dry-run`.

Установщик загружает проверенный релиз из публичного GitHub-репозитория. В скрытом
запросе получает текущую конфигурацию через Render API. На VPS записываются только
данные подключения к PostgreSQL, ключ расшифровки токенов и минимальные настройки
worker. Ключ администратора кабинета, Meta app secret, SMTP, платёжные пароли и
Render API key не копируются в постоянное окружение worker. Файл окружения
доступен только root с правами 0600; systemd передаёт переменные процессу.

Сервис запускается от отдельного пользователя с ограничениями systemd и
`VETASTART_SEND_ENABLED=false`: приём и подготовка черновиков без отправки.
Первое включение отправки — отдельный этап после проверки.
Проверка active в установщике подтверждает запуск процесса, а не полный рабочий
цикл: контроль времени последнего опроса после установки обязателен.

## Проверка после запуска

1. Убедиться, что `systemctl is-active vetastart-worker` возвращает active и
   журнал содержит только безопасные счётчики, без ошибок доступа к базе/Meta.
2. Проверить обновление времени опроса через защищённый API Render/панель владельца.
3. Только после этого выключить встроенный опрос на Render и повторно проверить
   обновление времени опроса. Во время перехода lease и уникальные event IDs
   защищают от повторной обработки, но два процесса не нужны постоянно.
4. Проверить новое тестовое сообщение. Автоматическая отправка пока выключена.

Внешняя бесплатная PostgreSQL Render всё ещё временная: этот перенос worker
не заменяет настройку постоянной базы и резервного копирования.

Установщик не переводит Render на платный тариф и не создаёт ресурсы Timeweb.
При неудачном запуске новой версии восстанавливается предыдущий worker, если
он существовал. Остановка: `systemctl stop vetastart-worker`; отключение старта
при загрузке: `systemctl disable vetastart-worker`.

## Локальные проверки пакета

`bash -n deploy/timeweb/install-worker.sh`

`python3 -m unittest discover -s deploy/timeweb -p 'test_*.py'`

Не запускать настоящий установщик в облачной рабочей среде: это пакет для VPS
владельца, а не изменение среды разработки.
