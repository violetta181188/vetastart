# Подключение Робокассы — 23 ноября 2026

Владелец показал статус «Активный магазин» для VetaStart. Заявка на активацию
выполнена. Это подтверждает допуск магазина со стороны Робокассы, а не готовую
интеграцию или проверенный платёж в приложении.

## Проверенные настройки приложения

На основном Render-сервисе платежи выключены, тестовый режим включён,
реальные платежи выключены. MerchantLogin и оба набора паролей отсутствуют.
Сайт vetastart.ru остаётся на существующем Timeweb; обработчик платежей находится
в PostgreSQL-приложении на Render.

## Технические настройки магазина

- MerchantLogin: взять из технических настроек конкретного магазина VetaStart.
  ID аккаунта в левой панели кабинета нельзя автоматически считать MerchantLogin.
- Алгоритм хеша: SHA256; в окружении приложения — ROBOKASSA_HASH_ALGORITHM=sha256.
- Result URL: https://vetastart-app-2026.onrender.com/webhooks/payments/robokassa
- Метод Result URL: POST.
- Success URL: https://vetastart-app-2026.onrender.com/billing/return
- Метод Success URL: GET.
- Fail URL: https://vetastart-app-2026.onrender.com/billing/return
- Метод Fail URL: GET.

Возврат в браузер показывает инструкцию проверки оплаты и не выдаёт платный доступ.
Доступ меняется только после проверенного подписанного Result URL. Для тестовой
операции счёт остаётся тестовым и платная подписка не активируется.

## Секреты и этапы

1. Получить публичный MerchantLogin и сохранить в ROBOKASSA_MERCHANT_LOGIN.
2. Настроить тестовые пароли, затем сохранить их только через защищённые поля:
   ROBOKASSA_TEST_PASSWORD1 и ROBOKASSA_TEST_PASSWORD2. Не присылать их в чат
   и не публиковать скриншоты с раскрытыми паролями. При переносе из секретов
   облачной среды в Render допустимый домен секрета — api.render.com.
3. После сохранения настроек включить только ROBOKASSA_ENABLED=true,
   ROBOKASSA_TEST_MODE=true, ROBOKASSA_LIVE_ENABLED=false и выполнить настоящий
   тестовый проход через Робокассу с проверкой подписи и идемпотентного callback.
4. Проверить требования кассы для самозанятого, чеки/фискализацию, описание услуги,
   оферту и возвраты до включения реальных платежей. Текущий адаптер не реализует
   регулярные списания, возвраты и полноценный поток фискальных чеков.
5. Боевые ROBOKASSA_PASSWORD1/ROBOKASSA_PASSWORD2 подключать отдельно после теста.
   Настоящий платёж не запускать без согласованной суммы и подтверждения владельца.

Платежи не включены этим документом. Повторное подтверждение доступа пользователя
к Timeweb для постоянного worker остаётся отдельной задачей.
